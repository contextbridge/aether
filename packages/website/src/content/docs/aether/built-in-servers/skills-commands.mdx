The `skills` server loads prompt artifacts from configured directories and exposes them in two ways:

- **MCP prompts** for `user-invocable` slash-command style workflows.
- **The MCP skills extension** for `agent-invocable` skills.

A single markdown artifact can be a user prompt, an agent skill, a read-triggered rule, or any combination of those surfaces.

## Configuration

Aether's project scaffold wires `skills` to `.aether/skills`:

```json title=".aether/mcp.json"
{
  "servers": {
    "skills": {
      "type": "in-memory",
      "args": ["--dir", ".aether/skills"]
    }
  }
}
```

`--dir` is repeatable. On name collision, the last directory wins. A skill is served at `skill://<skill>/SKILL.md`; same-named skills on different MCP servers are all listed and told apart by server and URI.

## Directory shape

Skills are directories with a `SKILL.md`. Slash commands and rules can also be flat markdown files directly under a configured `--dir`.

<FileTree>

- .aether/
  - skills/
    - rust/
      - SKILL.md
      - traits.md
      - error-handling.md
    - commit.md
    - rust-rules.md

</FileTree>

Skills can include supporting files that agents load on demand. Flat markdown files are useful for small slash commands or rules; they are not served as skills. Symlinks are not followed: a symlinked skill directory, or a skill containing a symlink, is not served.

## Prompt artifact frontmatter

```markdown title=".aether/skills/rust/SKILL.md"
---
name: rust
description: Rust conventions for this project
user-invocable: false
agent-invocable: true
tags: [rust, coding]
triggers:
  read:
    - "**/*.rs"
---

Use project-specific Rust conventions.

See `traits.md` and `error-handling.md` for detailed patterns.
```

| Field             | Description                                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `name`            | Required for skills, and must equal the directory name. For slash commands and rules it defaults to the directory name or filename stem. |
| `description`     | Discovery text. Required for skills; for slash commands and rules it defaults to the resolved name.                        |
| `user-invocable`  | Exposes the artifact as an MCP prompt. Directory-backed `SKILL.md` files default to `true`; flat files default to `false`. |
| `agent-invocable` | Serves a `SKILL.md` directory as a skill. Defaults to `true`.                                                              |
| `argument-hint`   | Optional argument hint for user-invocable prompts.                                                                         |
| `triggers.read`   | Project-relative glob patterns used as read-triggered rules by the coding server.                                          |
| `globs`, `paths`  | Compatibility aliases that also feed `triggers.read`.                                                                      |

Every authored artifact must have at least one activation surface: `user-invocable`, `agent-invocable`, `triggers.read`, `globs`, or `paths`.

## Skills over MCP

The `skills` server has no tools. It serves skills through the [MCP skills extension](https://modelcontextprotocol.io/extensions/skills/overview) (`skills/list`, `skills/get`, and `resources/read`), so other hosts that support the extension can use the same server.

Aether offers two tools whenever any connected MCP server serves skills, whether that is the built-in `skills` server or a remote one:

| Tool                  | Description                                                                          |
| --------------------- | ------------------------------------------------------------------------------------ |
| `aether__list_skills` | Return `server`, `uri`, and `description` for every served skill.                    |
| `aether__read_skill`  | Load a skill's `SKILL.md`, or one of its supporting files, by `server` and `uri`.    |

<Tabs>
  <TabItem label="Skill discovery">
    Recommended flow:

    1. Call `aether__list_skills` to discover available skills.
    2. Call `aether__read_skill` only for the exact skills needed.

    ```json title="aether__read_skill"
    { "server": "skills", "uri": "skill://rust/SKILL.md", "path": "traits.md" }
    ```

    Loading `SKILL.md` (no `path`) returns its body, followed by the supporting files the skill ships. Each file is checked against the size and SHA-256 digest the server lists for it, and files the skill does not list cannot be read. A skill whose server publishes no manifest (`"resources": "dynamic"`) cannot be digest-checked: its files are found by walking its directory and reads are confined to that directory.

  </TabItem>
  <TabItem label="User prompts">
    User-invocable artifacts are exposed through the MCP prompts protocol.

    ```markdown title=".aether/skills/commit.md"
    ---
    description: Generate a commit message for staged changes
    user-invocable: true
    agent-invocable: false
    argument-hint: "[optional context]"
    ---

    Generate a concise commit message for the currently staged git changes.

    Context: $ARGUMENTS
    ```

    `$ARGUMENTS` and named MCP prompt parameters are substituted when the prompt is requested.

  </TabItem>
</Tabs>

## Shell interpolation

MCP prompt bodies support Aether prompt shell interpolation such as `` !`git branch --show-current` ``. Commands execute relative to the workspace root. Skill content is served verbatim and never runs commands.
