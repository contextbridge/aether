---
title: Terminal UI
description: Run Aether interactively in the terminal.
---

The default way to use Aether is its terminal UI: a full-screen ACP client for chatting with project-local agents, reviewing tool progress, attaching files, changing settings, and resuming sessions.

```bash
aether
```

If no agents are configured in your user or project settings, Aether starts onboarding first. After onboarding, the terminal UI launches against the same `aether acp` server used by editor integrations. If you cancel onboarding — or the chosen provider's credentials still aren't set when it finishes — Aether exits instead of launching the terminal UI.

## Features

- **Streaming responses** — See model output as it arrives with markdown and syntax highlighting.
- **Tool tracking** — Follow running tool calls and sub-agent progress.
- **Plan visualization** — View task/plan status updates emitted by tools.
- **Inline diffs** — Review file changes in a two-pane [diff viewer](/aether/terminal/git-diff/).
- **Slash commands** — Trigger built-in commands and user-invocable MCP prompts with `/name`.
- **File attachments** — Attach files to prompts with the `@` picker.
- **Settings overlay** — Configure model, mode, reasoning, theme, and MCP server auth/status.
- **Session resume** — Resume previous ACP sessions.
- **Mouse support** — Click to focus and select, scroll to navigate diffs and lists.

## UI layout

```text
┌──────────────────────────────────────────┐
│  Conversation                            │
│  ├─ User messages                        │
│  ├─ Agent responses (streaming markdown) │
│  ├─ Tool calls (with progress)           │
│  └─ Plan entries                         │
│                                          │
├──────────────────────────────────────────┤
│  Prompt input          [@file] [/command]│
├──────────────────────────────────────────┤
│  mode · model · reasoning  ░░░░ · 45%   │
└──────────────────────────────────────────┘
```

The status line shows the active mode, model, reasoning effort, MCP state, and context usage. Segments are configurable in Wisp settings — see [Settings & Themes](/aether/terminal/settings/).

## Plan review screen

When an agent submits a plan for review, Wisp opens a full-screen review view with a heading outline on the left and the plan document on the right.

| Key | Action |
| --- | --- |
| `j` / `k`, `↑` / `↓` | Move the cursor through the plan or outline |
| `g` / `G` | Jump to the start or end |
| `n` / `p` | Jump to the next / previous heading |
| `h` / `l` | Focus the outline / document pane |
| `Enter` | In the outline, jump to the selected heading |
| `c` | Draft a comment at the cursor |
| `u` | Remove the last queued comment |
| `a` | Approve the plan |
| `r` | Request changes, sending queued comments as feedback |
| `Esc` | Close the review without a decision |
| `?` | Toggle the shortcut overlay |

Approving or requesting changes resolves the plan review and returns the decision — plus any comments — to the agent.

## Logs

When launched through `aether`, the terminal UI writes Wisp logs under `/tmp/wisp-logs` and uses `RUST_LOG` for verbosity.

```bash
RUST_LOG=debug aether
```
