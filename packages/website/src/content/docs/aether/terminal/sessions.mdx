title: Sessions
description: Session persistence, resume, and management.

Sessions represent a conversation with an agent. Each session has its own message history, configuration state, and working directory.

## How sessions work

Sessions are managed by the agent, not the terminal UI. Local Aether startup asks the agent to create a new session. A [remote client](/aether/running/remote/) instead resumes the server's live session, creating one only when none is active. The agent stores the session state — messages, config, and context — and the UI renders it.

## Starting a new session

```
/clear
```

This tells the agent to create a fresh session. The conversation history is cleared. When the new session exposes the same configurable options, Wisp restores the selections you were using before the clear.

## Resuming a session

```
/resume
```

This asks the agent for a list of previous sessions. A picker appears listing available sessions — type to fuzzy-search by title or path. When the terminal is wide enough, a preview panel shows each session's path, last-updated time, model, mode, tool-call count, and recent messages. Select one to restore it — the conversation history and configuration for that saved session are loaded from the agent.

## Remote detach and reattachment

Exiting `aether client` with the normal exit confirmation disconnects without cancelling or closing the session. Accepted work continues on the server. Run the same client command again to reattach to the same live runtime and session ID, including while a turn is running. The UI receives completed history, current configuration and running/idle state, then live updates. Partial chunks and pending dialogs are not guaranteed to return; pending interactions are cancelled rather than replayed.

Escape retains its separate cancellation behavior. An unexpected connection loss exits without automatically reconnecting or retrying prompts. Reattach and inspect the transcript before resubmitting an uncertain prompt.

Resuming the **live session** does not restart work. Selecting a **different saved session** deliberately stops the old runtime and restores saved conversation context. `/clear` is also deliberate replacement, not detach. After a server restart, use `aether client --session <session-id>` (with your server URL when needed) or `/resume` to choose saved history; interrupted tool execution cannot be restored.

## Session state

Each session tracks:

| State                | Description                              |
| -------------------- | ---------------------------------------- |
| Session ID           | Unique identifier                        |
| Title                | Agent-generated summary                  |
| Working directory    | The directory the session was started in |
| Config selections    | Model, reasoning effort, mode, etc.      |
| Conversation history | Full message history (stored by agent)   |

When you switch sessions, the configuration options that were active in that session are restored.

## Multiple sessions

You can have many sessions stored by the agent. Use `/resume` to switch between them. Only one session is active at a time.
